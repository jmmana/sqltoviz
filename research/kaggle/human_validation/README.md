# Human validation (100 reserved cases)

- `human_validation_100_cases.xlsx` - **the file for evaluators**: instructions (EN + ES summary), chart guide, 100 shuffled cases (SQL, result size, columns and first 20 rows) with drop-downs for preferred chart, valid alternatives, confidence and observations. It contains **no** LLM labels, model predictions, synthetic labels, stratum or provenance (checked by tests and by a scan of the real workbook; the only match for "llm" is the surname "Willms" in the data).
- `human_validation_key.csv` - case id -> internal item id. **Do not send to evaluators.**
- Return flow: `tools/ingest_human_validation.py KEY_CSV evaluator1=filled1.xlsx [evaluator2=filled2.xlsx]` validates answers (rows with no choice or "other" are reported as problems), writes `annotations/human_labels.jsonl` (label_source = human, kept apart from LLM and synthetic labels) and `reports/human_validation_report.json` (human-vs-LLM and human-vs-human kappa/agreement).
- Data are Spider-train queries (CC BY-SA 4.0, see ATTRIBUTION in ACQUISITION.md); suggest at least two independent evaluators so human-human agreement can be reported.

## Confirmatory path and dry-run (no human labels needed to test it)
- `tools/run_baselines.py synthetic|llm-agreement|llm-items` runs the rule, SQL-only, data-only, hybrid and hybrid+constraints systems and the LLM runs on the **non-human** tiers; every report carries `provenance` (synthetic or llm) and `confirmatory: false` (`reports/baselines_*.json`; the synthetic one uses 400 items per class, so it is smaller than the E1 run in `EXPERIMENTS.md`). The `llm-agreement` file scores each blind LLM run against the other LLM's labels: inter-LLM agreement, not accuracy.
- `tools/run_confirmatory.py KEY RESERVE_ITEMS HUMAN=xlsx HUMAN2=xlsx` is the confirmatory analysis of `PROTOCOL.md` (majority truth with ties listed for adjudication, classes with <5 human items excluded from macro-F1, 2000-resample paired cluster bootstrap with all pairwise differences, always-`table` baseline). It needs >=2 annotators and writes `reports/confirmatory_human.json` with provenance `human`.
- `tools/run_confirmatory.py --dry-run` exercises the same code (workbook, ingest, truth, analysis) on synthetic stand-in cases with random answers. Its files are named `FAKE_*`, are written to a temp directory, carry provenance `FAKE_DRYRUN`, and `write_report` refuses to place them in `reports/` or to mark any non-human tier as confirmatory (tests: `tests/test_confirmatory.py`). Its numbers mean nothing and belong in no table.

## Claude single-pass labels for the reserved 100 (NOT human)
`annotations/claude_labels_reserved100.jsonl` (+ `reports/claude_reserved100_report.json`) holds one blind LLM pass over the evaluator workbook, `label_source = llm_claude_reserved100`, `human = false`. It is kept apart from `human_labels.jsonl`, is not independent of the pilot Claude annotator, and does not replace human validation. See the report for caveats.
